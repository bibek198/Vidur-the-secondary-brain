# Evaluation results

Generated by `python eval/report.py` from the saved runs in `eval/results/`. All numbers are from the frozen graph `brain_eval` (2026-09-15) unless stated. Expected answers never come from the graph: they are read from the Kubernetes repositories with git at a fixed commit (`eval/truth.py`) or are the hand-verified gold labels (`eval/gold_decisions.csv`). Scoring is rule-based and identical for both systems (`eval/run_eval.py`); `eval/hand_check.csv` lists answers for a person to check the rule verdicts.

### Where each system failed

- Graph missed **A3** (Who knows the most about Improved multi-numa alignment in Topology Manager?): must name an author, approver or reviewer.
- Questions the vector search got right and the graph did not: 0.
- Vector search mostly failed by **saying the passages did not contain the answer** rather than by inventing one: it has no access to status, history, ownership or replacement links, and similarity search does not match a KEP by its number. It refused every invented lure, as the graph did.

Median time from publishing a change to the graph answering with it: **36.2 ms**.

All 6 graph misses are one KEP: the folder `keps/sig-node/2043-pod-resource-concrete-assigments` declares `kep-number: 1884` in its kep.yaml. The graph identifies KEPs by the declared number, so it holds this KEP as KEP-1884 (with the correct status) and honestly answered "not found" for KEP-2043, the number the truth builder took from the folder name. Counting it as a miss is deliberate; excluding it, the graph is 84/84.

Caveat, in the vector baseline's favour: design-doc passages are the 2026 text (only comments carry dates), so both vector variants can see text written after the checkpoint. The graph state is measured with the `trace_decision` tool directly (no LLM), the vector variants with the LLM over retrieved passages.

Raw rows: `eval/results/replay_20261018-0445.json`.
